# Current roadmap

The multi-tenant platform owns current sequencing and acceptance: [AgentEnvironment design](https://github.com/GuoMonth/dsh-multi-tenant/blob/main/docs/design/agent-environment.zh-CN.md), [main Issue #104](https://github.com/GuoMonth/dsh-multi-tenant/issues/104), and [platform roadmap](https://github.com/GuoMonth/dsh-multi-tenant/blob/main/docs/roadmap.md).

The target is Kubernetes-only AgentEnvironment. Current source still implements Cell; W1 source changes have not landed. W1 adopts the upstream core `Sandbox` CRD/controller as the sole infrastructure controller path: ordinary Pod, externally managed data/private PVCs, no synonym CRD and no fork. `Sandbox` remains an infrastructure object and the platform exposes only the narrow AgentEnvironment contract. Runtime #100 passed the bounded live check, including DSH HTTP/WS, stop/start evidence, PVC identity, deletion and negative target checks; see the [local evidence report](https://github.com/GuoMonth/dsh-multi-tenant/blob/main/docs/evidence/agent-sandbox-local-2026-09-23.md). W1 still must implement the production adapter and must not claim that W1/W2/W3 are complete. W2 retains the production gates for healthy-node stop/start, cross-resourceVersion concurrency, unknown deletion barriers and exact old-UID checks; no partition fencing. W3 jointly validates OIDC authorization, real tools, persistent HOME and release artifacts before publication. Backups, hot pools and automatic idle remain deferred. See the [current MVP implementation status](docs/alpha-mvp.md).
