# Current roadmap

The multi-tenant platform owns current sequencing and acceptance: [AgentEnvironment design](https://github.com/GuoMonth/dsh-multi-tenant/blob/main/docs/design/agent-environment.zh-CN.md), [main Issue #104](https://github.com/GuoMonth/dsh-multi-tenant/issues/104), and [platform roadmap](https://github.com/GuoMonth/dsh-multi-tenant/blob/main/docs/roadmap.md).

The target is Kubernetes-only AgentEnvironment. Current source still implements Cell; the source changes have not landed. W1 removes Process/Docker product backends, standalone launch, and snapshot/restore. Before W1, runtime issue [#100](https://github.com/GuoMonth/dsh-isolated-runtime/issues/100) is a bounded upstream selection check: core-only `Sandbox` CRD/controller, ordinary Pod, externally managed data/private PVCs, no synonym CRD and no fork; `Sandbox` remains an infrastructure object and the platform exposes only the narrow AgentEnvironment contract. If the thin adapter cannot preserve storage ownership, stop/start evidence, identity, credentials, and network boundaries, retain the current implementation. This is a prerequisite check, not a new long-term development round. W2 adds healthy-node normal stop/start on the selected implementation, retaining environment and both PVC identities without partition fencing. W3 jointly validates real authorization, persistent HOME and performance before release. Backups, hot pools and automatic idle remain deferred. See the [current MVP implementation status](docs/alpha-mvp.md).
