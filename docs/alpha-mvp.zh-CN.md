# 自托管 alpha MVP

状态：已确定的产品方向，实现与验收尚待完成。企业自托管是长期目标，不代表当前已经
生产可用。下一阶段优先投入本方向，不再扩展桌面安装体验；本决策不修改已发布的
v0.2.0-alpha.1 产物、精确 DSH 基线或 Cell/CellSnapshot 契约。

## 用户与责任

企业统一部署，为用户提供浏览器可访问的云端 DSH 环境。安装维护者必须拥有 Kubernetes
集群运维权限；最终用户只需获授权的身份，不需要 Kubernetes 权限。企业研发可自行准备
本地集群，复现核心技术流程。

管理员负责集群生命周期、网络、存储、DNS/TLS、OIDC 身份源、namespace 与访问授权。
本项目负责运行时组件和 Cell 调谐；DSH 负责会话、工具和模型使用。保留现有 namespace
及资源所有权边界。

## 下一里程碑

- 单集群、一套明确的参考部署拓扑。
- 优先采用版本化 Helm chart，绑定经过验收的镜像 digest。Helm 尚未交付；实现前先明确
  资源归属和 CRD 安装升级顺序。Helm 回滚不等于 DSH 数据回滚。
- 沿用现有 Envoy Gateway 访问链路，写明依赖，不承诺任意 Ingress 或 Gateway 实现兼容。
- 使用标准 OIDC 接入个人身份，验证一个提供方配置并明确稳定身份到 RBAC 的映射。
  管理员通过 RoleBinding 显式授权，登录成功不自动获得 Cell 访问权。不开发账号系统、
  企业目录同步或自动组授权。
- 管理员通过声明式配置创建 Cell 并分发访问地址。“一人一个环境”只是参考流程，
  不固化为 API 限制。暂不建设管理后台或自助开通功能。
- 明确可用 StorageClass 前提，验证 Pod 重建后数据保留。快照保持可选，不扩展为备份服务。
- 提供一条 kind 参考路径，使用相同 chart 和镜像。研发自行准备和管理集群；项目说明
  测试网络、存储、身份和入口配置，不重新建设宿主机工具、浏览器或集群生命周期管理器。
- 提供基本就绪状态、日志和排障说明。安装成功不等于用户流程可用。

目前已有集群仍使用 config/default、config/browser、config/snapshots 下的 Kustomize
入口，待 Helm 实现和验证期间继续保留。此次决策不新增 k3s 或其他配置的支持承诺，
支持范围随验证证据逐步扩展。

## Alpha 边界

暂缓生产可用性与容量 SLO、高可用建设、自动扩缩容、多集群、全面审计、完整灾备、
离线发行、广泛基础设施适配及自动数据迁移。保留已经实现的能力及回归测试，暂缓不等于删除。

即使是 alpha，也必须满足以下底线：

- 拒绝未认证、未授权和跨 Cell 访问；授权失败时拒绝访问，明确 NetworkPolicy 执行前提。
- 如实说明普通容器隔离边界，不宣称已验证恶意代码强隔离或未经验证的沙箱运行时。
- 不静默删除数据。说明破坏性操作及运行时卸载重装的保留范围；用户 Cell、租户 namespace
  和业务数据不应因移除运行时 chart 而被顺带删除。
- 凭据不进入日志和验收证据，保留产物身份校验，明确不支持的升级与恢复操作。
- 不把下次请求撤权等同于终止已有连接或执行任务，不把本地测试成功等同于生产验收。

## 验收

记录版本、镜像 digest、集群前提、命令及脱敏结果。新建 kind 参考环境和一个有代表性的
已有集群都完成下列流程，才能宣布下一里程碑完成：

1. 按文档从指定产物安装，无须修改项目代码；对不满足前提的情况给出可定位的错误。
2. 两个 OIDC 身份、两个 Cell，显式授权后各自可用，未认证及跨 Cell 请求被拒绝；
   撤销授权后下一次需要授权的请求被拒绝。
3. 在 DSH 完成真实模型调用及唯一文件写入、读回，凭据由用户私下输入。确定性模型测试
   继续作为回归证据，但不代替本次记录的真实模型检查。
4. Pod 重建后仍能访问原文件和会话。
5. 在测试专属资源上完成运行时卸载重装，验证 Cell 数据保留且重装后能够恢复调谐。

启用快照时另行验收。如实记录失败和未执行项。kind 结果不能证明其他 CNI/CSI/IdP
组合、生产规模或 Mac Docker Desktop 已通过验证。

## 发行过渡

不再扩展 npm 和宿主机管理式本地安装产品能力。保留历史发行物、对应版本的恢复说明，
以及有价值的本地和 kind 回归测试。不删除或静默迁移已有状态。已发布版本继续使用其
安装说明；本文不引入可执行的 Helm 安装命令，也不代表新版本发布。

自动 CI 仍仅执行 Source standards。实现变更按影响范围本地验证，并在 PR 记录结果。
chart、镜像、npm 包或 release tag 的发布仍需单独发行授权。
